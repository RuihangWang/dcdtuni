# CPU OpenUSD result-layer authoring (isolated branch)

**Candidate:** `codex/ov-result-usd-cpu-20260927@4f302279`; the main branch retains this evidence, not the unconnected adapter.

`src/frontend/omniverse/cfd_demo/kit/extensions/dc.cfd_bridge/dc/cfd_bridge/result_layers_usd.py` consumes the exact `dcdtuni.render-result-layers/v1` schema from `src/frontend/shared/schema/render-result-layers.schema.json` (the `a5632e11` contract). It writes a separate `/World/RenderResultLayers` subtree. The editable `/World/RenderScene` and `.cfdproj` remain untouched. This module is not yet called by an OV command or a React producer.

The caller must pass an independently current `expected_source` and `expected_time_seconds`, plus the last accepted revision if it tracks one. The adapter validates the packet, source identity, mesh quality, complete index/value spans and revision before changing the stage. Repeated revisions for the same source are rejected even without an external sequence tracker. A diagnostic mesh may produce edges only; physical scalar surfaces and streamlines require an accepted mesh, run receipt and sample time.

Each boundary USD prim retains `meshPatchName` and the **entire** sorted `sourceFaceUids` array. A merged patch therefore remains one patch-level scalar field; it is not split into fictional per-source fields. The root retains project, `.cfdrun`, mesh, run, physical time and revision identity. `meshEdges` become linear curves over the original edges; `surfaceField` becomes a triangulated mesh with a vertex `dcdtuniRawScalar` double primvar; streamline paths become linear curves with the same raw primvar. Scalar layers carry the field and unit, a 256-entry LUT-derived vertex `displayColor`, and a bound `UsdPreviewSurface` material. This is a USD-compatible baked display approximation: interpolation *between* vertex colors is not equivalent to Three.js's per-fragment LUT lookup. Actual RTX pixels still require a GPU-authorized OV test.

The Python module imports `pxr` only when authoring. It adds no package dependency to Kit and makes no network or GPU calls. Tests use a synthetic three-source-face aggregated patch, a surface field and two streamline paths; the USD is exported and reopened on 40901 CPU. They do not establish that Shinaide's current wind mesh or a measured NV field is physically accepted. The patch-to-source mapping itself must be proven by the mesh source compiler and matching receipt before a live packet is published. The receiver must obtain `expected_source` from its current selection, not echo the packet's own source object.

The isolated `a5632e11` React result-layer branch still has an expected orphan-module audit failure until a real producer, transport command and Kit receiver are connected. This CPU authoring adapter does not resolve that integration or the previous OV video/ACK failure.
