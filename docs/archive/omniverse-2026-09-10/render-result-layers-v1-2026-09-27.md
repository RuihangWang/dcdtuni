## Identity and display contract

`dcdtuni.render-result-layers/v1` carries a monotonically increasing revision for each project/run/mesh source, the saved project UID and SHA-256, the executed `.cfdrun` SHA-256, the mesh receipt SHA-256, an explicit mesh-quality state (`accepted` or `diagnostic`), and either a run UID plus run receipt SHA-256 or an explicit `null` run for pre-solve mesh preview. It fixes metre/Y-up/right-handed coordinates. A physical sample time is required for scalar results and `null` for an unrun mesh. Diagnostic meshes may show edges for inspection, but scalar field/streamline layers require `accepted` quality. Boundary layers carry the OpenFOAM `meshPatchName` and a **sorted, unique, nonempty `sourceFaceUids[]`**. The mesh patch's identity is `(meshReceiptSha256, meshPatchName)`; the face list records source lineage and is not a substitute for that identity. Streamlines can originate in `internalMesh`, so they carry a seed UID instead of inventing a boundary patch or editable `modelUid`.

The union has `meshEdges`, `surfaceField` and `streamline`. Mesh edges are original polygon edges from the decoded mesh, not triangulation diagonals. A `surfaceField`'s raw scalar values belong to the **aggregated mesh patch vertices**, even if that patch collects several source faces. The packet cannot infer or claim a separate physical field for `con_f`, `con_b` or `con_b_copy` from one `merged_wall_baffle` patch result; doing that requires a verified per-face mesh mapping not present here. Streamline scalar samples belong to the integrated paths and their seed UID, not to boundary source faces. Field-bearing layers retain the physical field name/unit and a declared preset LUT with an ascending range and opacity. A renderer may implement its own shader from these values; the packet cannot carry `ShaderMaterial`, a Three.js object or an editable model UID. The validator rejects unknown fields, malformed hashes, repeated layer IDs, inconsistent source-face lists for the same mesh patch, invalid index/point spans, non-finite values, missing run/time for scalar data and non-ascending LUT ranges.

`resultLayerAdapter.ts` converts existing `DecodedMesh` and `StreamlineSet` data on CPU. It requires an explicit map from every mesh patch name to its complete sorted source-face UID list and rejects absent, empty, unsorted or duplicate mappings, including on hidden patches; it also rejects patch-local indices outside the patch point span. The adapter validates the supplied list's **shape and consistency**, not its geometric completeness. Before publishing, the caller must independently prove the full patch-to-source relation from the same mesh source receipt and source-surface compiler; neither patch-name matching nor a nearest-face guess is acceptable. `resultLayerRevision.ts` provides an independent accepted-packet event; delayed packets are rejected against the *current* project/input/mesh/run/time/field identity, and revisions cannot go backward for the same source. Its decoded-boundary entry point publishes a mesh-edge plus surface-field packet. The event is intentionally **not yet connected** to the active React panel, model snapshot or OV command stream: those routes currently lack an accepted run/mesh receipt and a proven full patch-to-source mapping. Importing this module just to silence `orphanModules.test.ts` would give a false impression of working OV result display.

## CPU verification and remaining integration

The tests use a two-patch decoded mesh, a three-source-face `merged_wall_baffle` fixture and the repository's actual decoded `pp_streamlines_small.bin` sample. They cover JSON round-trip, polygon edges, aggregated patch-level field values, raw streamline values, hidden patches, provenance/time/field mismatch and invalid geometry. A source binding must come from the strict mesh source receipt; callers must set quality from the real `checkMesh` gate, not from a desired display state. The current Shinaide wind mesh fails `checkMesh`, so its edges may only be labelled diagnostic and its data must not be used as an accepted physical field or as renderer acceptance evidence.

To make this a live renderer feature, compile or retrieve verified run and mesh receipt hashes and the exact mesh-patch/source-face map from the same `.cfdproj`/`.cfdrun` revision; publish packets on mesh/field/time/visibility changes and clear them on project/run invalidation. Then extend the OV transfer protocol and Kit bridge to receive these separate packets, author mesh edges and scalar materials, return revision-correlated ACKs, and keep React's Three and OV adapters on the same layer state. Only a later authorized GPU session can check OV pixels and editing interactions.
