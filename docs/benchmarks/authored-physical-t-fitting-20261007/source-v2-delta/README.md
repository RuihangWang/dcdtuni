# Authored T fitting: incremental split semantics v2

This is a **four-path delta applied after the immutable authored fitting FROZEN-v1**, not a replacement fourteen-target package. No normal source, saved case, liquid graph, MMS fixture, original thirteen STL inputs, GPU, or product service was modified by this task. D remains the clean public 66225277 source; T is the private copied ea922 source plus fitting v1 and this candidate.

## Primary audit and allocation decision

The complete source files are under `primary/`, and the original scoped query argv/results are `query1.log`…`query13.log`. The initial split API was the production `window._upgradeToTBranch`, with real store and real installed bridge factories.

- `cfdproj_migrate.js:464–483` puts the original `pipe.valves` into `cooling.valves`, and preserves `connection.blindEnds` and `connection.junctions`. The old split copied diameter/spec/role and endpoint IDs but recreated these containers without their declarations.
- `liquid_graphgen.js:621–647` defines start blind flags at the first waypoint and end blind flags at the last waypoint. These are uniquely mapped: A inherits the original start flag, B inherits the original end flag, and both new junction-facing ends are false. The API controls assert the retained endpoint waypoint coordinates and actual junction port IDs.
- `cfdproj_schema.js:313–361` declares pipe-owned valves, optional physical branch diameter/waypoints, and same-pipe series references for flow control/isolation. It supplies no rule to assign those owned records to the new A/B pipe IDs after splitting. A nonempty valve list therefore causes refusal before the checkpoint, either factory, model removal/addition, store notification, map edit, geometry rebuild, or selection.
- `connection.junctions` is preserved by migration but has no element/allocation contract in the audited sources. The negative test uses an explicitly opaque declaration, not an invented known junction topology. Any nonempty declaration is refused without interpreting it. Non-array valve/junction containers and malformed/unknown blind flag fields are also refused, rather than dropped.
- `liquid_mode.js:1522–1538` creates actual inline fitting records in `cooling.valves`; the flow-control and tee/branch fixtures use those real field names. No synthetic pipe-owned pump field was introduced.
- `liquid_graphgen.js:373–389` reads actual CDU `constructions.pump` for advanced pump RPM. Separately, `liquid_pipe_renderer.js:809–837` authors `{pump: specName, rpm:3000}` into network chain paths. `react/src/legacy/liquidScene.ts:316–323` defines canonical net_main creation. These have different owners from the split pipe. The positive control creates a real CDU and canonical independent chain pump record, splits the plain pipe, and asserts both external owners are unchanged. The refusal is **not** a global pump prohibition.

The product patch moves the original pipe cooling/connection reads before all mutations, adds the narrowly scoped refusal and translated explanation, and copies the two known outer blind flags. Existing empty/absent declarations remain usable; ordinary 73 mm diameter inheritance and original role/endpoint semantics are retained.
