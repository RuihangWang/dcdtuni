# Domain geometry/material/physics carriers: next-stage implementation plan

This is a selected-source, read-only plan after the successful normal IT foundation build. Source SHA/line counts and related frozen proofs are in source-identity.json. No Stage 2 source, tests, build, business run, browser, service or Git operation was performed.

The completed foundation preserves plain JSON identity/compatibility. BaseEntity.ts:23-65 still returns record-backed geometry/render/physics declarations, and most named classes at :70-135 inherit behavior. This does not yet fulfill the requested behavior-owning OOP geometry/physics architecture or qualify SimReady/DSX.

## Actual seams and smallest real vertical slice

SceneBuilder.ts:339-365 delegates all shape construction to shared geometry_scene.js, then :367-382 adds display-only PDU/liquid detail outside the physical renderMeshes registry. The initial actual seam is geometry_scene.js:2236-2316: BOX/CDU face island clipping, triangulation, layout transform, per-face opacity/UV/material role and exportName assignment. Extract this existing algorithm into ONE numeric product kernel; both the legacy wrapper and BoxEntity/CduEntity methods call it. Calling SceneBuilder and exporting its finished objects from a new class would remain a facade.

Proposed GeometryProduct is data-only: source address (project UID/path/parent/UID), deterministic semantic part key, local positions/indices/normals/UVs, double transform matrix, source face/patch refs, exportName, explicit physical/display/helper role, and material reference. Three is an adapter allocating BufferGeometry/Object3D and resource lifetimes. Domain method outputs must not contain THREE objects, window, scene registries, GPU textures or mutable store calls. Numeric typed buffers preserve the current Float32 geometry conversion stage and Float64 transform arithmetic/order; exact old STL bytes/normal winding/solid order remain the acceptance baseline. Preserve polygon-clipping order, triangulation order, degeneracy thresholds, mirrored winding and six-decimal STL formatting; do not replace them with merely visually similar geometry.

In the same slice extract model pose and equipment port math from geometry_pure.js:240-307,353-378. Quaternion normalization, non-uniform/mirrored scale, anchor translation and rack manifold/slot offsets must match current arithmetic. CduEntity/RackEntity/PipeEntity physics methods consume the same neutral frames that the renderer uses. Legacy wrappers return THREE.Vector3 only at the compatibility boundary. These are actual geometric calculations; a record descriptor is not a port implementation.

MaterialRecipe owns semantic role, color/roughness/metalness/normalScale, side/opacity, texture reference/hash and UV policy. Keep procedural texture generation/loading and shared texture caches in adapters. Existing geometry_scene.js:2404-2441 and shared/pbr_materials.js:73-82,177-200 are the single role/default sources. Migrate values without retuning. Runtime selection, opacity, result coloring and restore/dispose are view layers; they must not change physical geometry or project declarations. CDU private paint/HMI material and display-only internal decoration remain distinct from authored external physical pipes/ports; legacy named PDU boxes do not become an electrical model.

## Real Three / OV / physical export connection

SceneBuilder buildAll:479-549 currently enumerates shared stateV4 models and places/rotates root groups. Replace per-class construction incrementally with DomainProject products; preserve current ordering, modelMap, renderRoots/renderMeshes and ownership tags. Require explicit operations for all 18 registry buckets, room/singletons and authored child families (coverage matrix in carrier-plan.json). A transitional named legacy strategy must be explicit; a missing imported asset is a marked preview failure/placeholder, never silent authorization to export a box. Network/definition/instrumentation records may legitimately have no physical triangles and must say so.

sceneSnapshot.ts:416-539 presently reads live Three. Its existing wire schema (:59-67) and Kit consumer render_scene.py:378-461 already provide neutral triangle/material/matrix input and in-memory USD. A new domainSceneSnapshot adapter can lower GeometryProduct to the SAME packet while a Three compatibility adapter remains for not-yet-migrated classes. Do not duplicate geometry calculation in USD or introduce a new cfdproj authority. Preserve equipmentUid/liquidPart/valve-owner, instancing, group/material partitions, texture matrix/flipY, normals/colors, visibility, camera/view state, result-layer source hash and ACK.

Current primitive ID is uid/path/instance/materialGroup (sceneSnapshot.ts:497); path is Three child traversal (:535). Add stable component identity based on entity address+semantic part, with a deliberate compatibility/old-ID binding during migration. Do not silently change primitive identity before selection/highlight/result/ACK tests pass.

Physical STL currently reads rendered meshes (io/stlExport.ts:34-45, shared/stl_writer.js:78-110). In the first slice Three meshes and STL are produced from the identical neutral physical product; in the eventual direct writer, consume the same buffers/order and existing naming kernel. Decorative HMI, handles and cabinet detail never join physical export. runSubmit.ts:95-116/runPayload.ts:147-154 must bind manifest and grouped STL from one owned compile batch; eliminate window._meshExportGroupedMap only when that same ownership is explicit. Never rebuild different tessellation for the manifest.

## Real physics ownership and run boundary

Liquid graph input is JSON, not a live scene traversal. dynamicLiquidGraph.ts:52-81 clones and UID-renames a private compile snapshot; shared liquid_graphgen.js resolves ports through geometryPure/THREE and global state. Evolve the EXISTING single compiler to an explicit context (project/models, neutral port resolver, parameter library, diagnostic sink), not a second independent compiler. See liquidRunGraph.ts:33-58 and legacy/liquidGraphgen.ts:58-88 for compatibility global guards.

Domain physics fragments contain actual port addresses, connections, unit/source provenance and existing typed parameters; the compiler aggregates them in current order. Keep cpCuPairs as the sole cold-plate physical membership/value list (dynamicLiquidGraph.ts:59-74); constructions.coldPlates supplies historical UID backing, not a duplicate physical branch. Rack-local server UID parent paths, pump/HX/valve identities, explicit isolation valves, object_bindings, node/edge order, profiles, SI conversions, schedules/events and source/config hashes must remain unchanged. Never infer physics from display names or displayed visibility. Unknown physical interfaces produce structured refusal while source records remain saveable.

Air ResolvedRun (cfdrun_reader.py:89-115,471-530) is already the typed BC/porous/source-term/solver lowering target. Entity physics methods should supply stable face/source role and authored parameter fragments to that existing lowering, preserving sourceSurface/objectPath/solid/patch bindings. Shared cfdrun_export/build remain the single strict serialization producer while moved code shares one kernel. Unknown document extensions remain in authoritative cfdproj but never get spread into strict cfdrun/liquidrun schemas.

A RunSnapshot must capture source project/hash/input revision, t0/materialized transient intent, compiled manifest, geometry/source hashes and owned buffers/bindings once. Do not hand mutable Entity.record or live material references to async workers. Refresh/generation checks after await remain necessary. Cache keys for rendering must include store rendering revision/materialized playhead, not only documentInputRevision: projectStore.ts:191-200 materializes playback without increasing the input-edit clock. Physics admission/input hash remains the canonical saved timeline, independent of viewing playhead.

Current frontend creates cfdrun+STL in RAM (runPayload.ts:132-155,session.ts:416-427), but server.py prepare-case/run paths stage/write these and execute a pinned disk --from-cfdrun runner. This is NOT a RAM-only full pipeline. A later input-provider/session task may hold validated owned bytes while retaining explicit artifact/case/mesh I/O; it needs separate lock/cancel/worker identity tests. Keep current file identity guards until that real replacement exists.

## Bounded migration order and acceptance

1. Add neutral products, numeric pose/ports and material roles; no persisted schema/default changes. Implement BOX/CDU patched shell kernel once and connect the actual scene/STL/snapshot chain.
2. Extend named classes over planar wall/floor/baffle/openings, then rack frames/server hierarchy and liquid pipes/junctions; maintain the explicit 18-bucket capability matrix. CSG/imported assets retain a clearly named legacy bridge until a single neutral tessellator is verified. No automatic boxing of unsupported kinds.
3. Migrate the sole liquid compiler to explicit neutral context and real per-entity physics fragments; preserve existing strict graph inputs byte/semantically and resolve all authored child bindings once.
4. Capture one owned air compile bundle/RunSnapshot, then move remaining geometry/material classes and snapshot producer to neutral products. Only afterwards consider a backend accepted-bytes session; do not mix it with this frontend port.
5. Verify each slice before claiming complete carriers or external standards support. DSX/SimReady fields and validation depend on ROOT's official-source research and real consumer acceptance; no certification follows from class names/customData.

Meaningful gates: existing sceneBuilder/Preview, patchGeometry/rackGeometry, cfdrunStlIdentity/rackExportNaming and direct old-vs-new buffers/STL/source-role/hash tests across all registered strategies; room/holes/imports/negative transform/nonuniform scales and explicit unavailable assets; original material snapshot/clear/dispose/highlight/fade/face-image UV tests; sceneSnapshot/Pbr/Shinaide packet identity equivalence and Kit test_render_scene.py CPU validation; LiquidSingle and actual Shinaide mixed input node/edge/port/member/order/parameter/grid/event/source hashes before/after; canonical save/load/undo and unknown-field preservation. ROOT then performs real Three↔OV and physical export UI, plus the fixed mixed trajectory runtime comparison. Static adapter tests do not accept native full mesh/solver or arbitrary scientific gradients.

The independent Stage 2 plan (related evidence manifest in source-identity.json) agrees: JSON liquid inputs are not live meshes; window/THREE math is the debt, air remains a pinned file execution, owned texture cache still performs explicit I/O, and typed run snapshots are derived. This note adds a concrete numeric BOX/port vertical slice and output-order/cache/identity guards. No extra implementation authorization is implied.
