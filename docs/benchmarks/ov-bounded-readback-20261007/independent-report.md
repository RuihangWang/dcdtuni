## Wording and acceptance boundary

The class docstring at247–248 says identity is checked “after them,” and the comment at300–301 says “after all getters.” Those phrases should describe only the specific captured context/material/path/time checks and the two named observation collections. They should not be expanded into a claim that every observed field is rechecked after every later getter, that all domains form one atomic epoch, or that arbitrary reentrant/concurrent writers are rejected.

Suggested precise wording: “With the fixed synchronous readonly producers, compare two bounded view/renderer/public-sampler/authored-camera observations around the final timing callback, then compare material and source/path/time context. This is a consistency check of those collections, not an atomic native frame or concurrent-writer guarantee.” Documentation can be narrowed at the next Root checkpoint without changing the fixed producer contract or inventing an unbounded last-getter loop. If a new producer introduces callbacks/await or concurrent writing, this scoped acceptance must be revisited.
