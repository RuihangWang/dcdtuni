# Minimal unimplemented proposal

B0, first separate readonly observation proposal: under the existing default-off bounded diagnostics profile, source-gate Window.app_window and compare its exact native association with the owned default IAppWindow. Also read the public legacy delegate size and ImageProvider width/height/validity. Keep UI-point/raw units explicit; do not dereference the image resource. These values could identify texture-vs-app aspect or a viewport on another OS window. They do not expose the private image rectangle or encoder layout and create no grid permission. Root should first inspect actual A delivered projection/resolution, canvas projection/resolution, outer frame and framebuffer dimensions, then decide whether B0 is needed. No new frontend UI.

B1, only after explicit review/approval: install one owned ViewportDisplayDelegate subclass through the public setter on the already acknowledged active widget. Its create receives the actual inner ui.Frame. It owns only its own ImageWithProvider and references the supplied public image provider; its update passes the opaque texture directly through the supported ImageProvider path, with no resource extraction/copy/readback. Keep local owner/API/app/window/stage/current scene+complete-view generation fences. Retain the public Frame and own Image object so their public screen positions/content dimensions and explicit IWP_PRESERVE_ASPECT_FIT + centered alignment are measurable. Read the own Image's actual policy; do not infer legacy defaults. The explicit policy is a future display change that needs pixel/picking validation, not an automatic repair. Do not stretch the picture simply to match an expected ratio.

This can produce a truthful texture-to-owned-image contract: provider texture dimensions, exact API referent/render product, declared fill policy/alignment, observed image and inner Frame values. It must not promote raw UI computed dimensions into physical pixels by assumption. Screen positions are documented ScreenPixel; computed sizes are not. The vendor's fill-frame path multiplies UI computed size by Workspace.get_dpi_scale (widget614–643), while app.get_ui_scale includes DPI and a UI multiplier. Those distinct getters cannot be substituted. Resolve physical bounds with independently checked public measurements/calibration under the exact app-window owner, or retain physicalRect unresolved.

Only after that relationship is demonstrated can texture UV be mapped through the actual fit content rectangle into the whole app framebuffer. React decoded intrinsic size and CSS contain transformation remain a separate current owned-media producer. Keep anisotropic/nonzero dimensions, viewport/API/app replacement, resize, scene/view advance and delayed/update cancellation conservative; cached expected aspect is never proof. Native app9 whole-frame architecture is source evidence, not a per-frame encoder receipt. If public runtime layout evidence or a Root-owned static calibration cannot establish framebuffer-to-decoded-raster mapping, retain encodedLayoutProof unresolved and do not grant new rendered-grid ACK.

Lifecycle: native default off; wire cannot enable; one active widget/delegate; capture previous delegate through its public getter before install. Restore only that exact owned widget on disable/shutdown/owner change. Destroy only the new delegate's own UI objects, never a borrowed provider or texture; delegate source defines public restore/create hooks. Changes to current accepted stage, camera/time/render product/full view retire observations immediately. No new app window, force-frame, freeze, fullscreen, camera/projection setter, stream endpoint or capture delegate. Headless/zero/unknown source returns unavailable, preserves legacy fallback. Scientific/source/pick authorities remain unchanged. Custom image/layout changes must be checked with existing source-pick positions rather than bypassing them.

Required future private checks before any Root live use: actual public delegate setter/create/update path and strong/weakreferent owners; exact policy/center-fit content math; shared provider restoration/disposal; API/window/app rebind; same-tag different owner; zero/oversized/unknown dimensions; WorkspaceDPI distinct from appUIscale; pending resize/cancel/late update; default-off and legacy fallback; no science/source/UID mutations. Root's later actual run must independently compare displayed projection/extent and source picks against Three. Calibration is not invented capturedFrameID; same-frame proof remains unresolved unless a real supported identity becomes available.
