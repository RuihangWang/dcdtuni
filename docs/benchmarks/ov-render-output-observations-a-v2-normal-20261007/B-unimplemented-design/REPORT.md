This package-only absence is not a claim about unpublished C++ implementations. Browser decoded size is not the window frame size or a common native frame ID.

The genuinely missing observations are (1) current texture content rectangle in physical application-framebuffer pixels with owner/window/units proven; (2) this framebuffer's crop/scale/letterbox relationship to each delivered decoded raster, including the stream's actual source-window association; (3) a documented common render/present/encoder frame identity if same-frame claims are required. Metadata, requested size, matching aspect or a presentation_key cannot fill them. A stable scene/view can support a carefully bounded static layout measurement later; it cannot manufacture encoded same-frame provenance.
