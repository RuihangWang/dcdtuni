# Minimal layered private repair design

This design follows actual job420920b2 and the source/geometry bindings in REPORT.md. It is not a production patch and does not assert a complete passing mesh.

1. Make W-SB3 collinear simplification a shared topology transaction. Its present face-local deletion at Cartesian.cpp34306-34307 occurs after the S11b closed-edge gate. Retain the exact ==0 geometric criterion. A removable point must be collinear in every face containing it and must be removed consistently from all of those rings; reject a proposal if any affected owner/neighbour cell loses its degree2 directed-edge invariant. Keep minimum3 points, nonzero area, patch identity, owner/neighbour order, outward orientation and determinism. Add a strict post-mutation edge validation after every topology-changing export pass. Neither bypass W-SB3 nor add a new flag.

The generic proof implementation safe_prune is in proof_preview.py. It accepts a known closed point-ID mesh, builds all point/face and cell/face incidence, proposes points in increasing ID order, and commits only a complete incident-ring transaction preserving closed edge counts. The existing actual coordinates yield no deletions on the reconstructed closed mesh because each required conformity vertex is a corner in at least one incident face. This proof intentionally uses no actual cell/face IDs or coordinate triggers in its algorithm. It is not a frozen C++ diff, a compiled test or an observed native pre-prune snapshot.

Simply deleting each point when it is collinear in one face remains unsafe. A one-pass local repair also remains unsafe: the preserved one-pass proof shows propagation to24 other cells. Do not hardcode236 points,74 cells or four face IDs. A production implementation should operate on the already-conforming pre-W-SB3 rings, preserve all existing caps and use the final edge gate to fail closed if simplification is incomplete.

2. Add true convexity and decomposition validation to the existing S9b candidate transaction. Reuse trySplit17279 rather than build an independent exporter. Preserve the existing volume minimum, piece closure, original centroid checks, skew/quality checks, neighbour staging, partner matching and all native gates. Strengthen candidate acceptance to require every staged child and affected neighbour to satisfy the relevant native convexity and face-tet predicates. A centroid lying inside every face plane is only a kernel condition; it is not convexity. Every child vertex/face centre must remain within the complete oriented face halfspaces. Every exported face-centre fan must retain the correct tet sign in its owner and neighbour, and a valid common vertex base must also exist.

The population condition at splitOneCell18255, scan18972 and candidate allGreen18347 currently see only foam-centre halfspace violation. The proposed private quality-driven path must also see positive face-plane violations, true reflex features, face-centre fan failure and the installed planar-partition gate. Passing children must strictly resolve the selected defect without weakening the original centroid or other gates. Merely changing population while keeping trySplit's centroid-only score/no_improvement tail will not work for already-centroid-inside children.

Do not prescribe the actual diagonal positions or axes. Generate candidates from current physical face planes and reflex geometry using the existing clipRing/trySplit machinery. Prefer a legal convex volume partition when a radial plane leaves nonconvex children. A next preview must distinguish every predicate and rejected candidate, rather than rename centroid allGreen as full quality.

3. Resolve coplanar tiled faces conformally. All66 planar-only cells fail the actual strict face-plane gate even after closed edges are restored. Coalescing coplanar polygons is legal only if their complete owner/neighbour pair, physical patch/role and geometric support permit a single simple polygon, and both sides are updated together. Different neighbour IDs or different physical roles cannot be merged merely because normals match. Where a coarse cell meets several fine neighbours, use legal cell/cavity repartition aligned with the seam geometry and propagate neighbour updates until shared full faces conform. Preserve the original fluid union and solid boundary.

Face triangulation alone adds coplanar pieces and cannot prove the strict cell gate. It also cannot turn the eight nonconvex L-shaped volume cells into convex cells. Selecting one of the available vertex-base fans only changes a decomposition choice and does not resolve the observed face-centre fan or volume convexity.

4. Add conservation proof to each private candidate. Before and after a transaction, retain the exact oriented cavity boundary, same physical patch/role surfaces and internal shared-face cancellation. Require closed directed edges, no orphan/multiple partners, positive child volumes, Vsum=Vbefore and M1sum=M1before, independently under at least two reference origins. Validate every changed neighbour as well as the split parent. Record owner/neighbour and source-origin maps; geometry alone must never substitute for an actual ID provenance witness.

The controlled read-only audit already freezes the correct whole-case targets: V511/512, M1(4091,4087,4091)/8192. The old four S10 boxes each have legal partitionV15/32768 and exact first moments in old-s10-to-actual-geometric-partition.json. Their lawful lower wall halves must remain present. These are regression evidence and conservation targets, not case selectors for a general algorithm.

5. Stage review and native acceptance. The next smallest source preview should first implement the shared-topology safeguard plus its final failure gate and test general coarse/fine shared-vertex arrangements. That preview alone cannot be accepted as a strict full repair: retained collinear points may expose prior vertex-base degeneracy, and66+8 cell checks remain. A separately reviewed convex/conformal transaction preview must demonstrate complete changed-cavity quality and preservation. Only then should ROOT decide on a normal build and normal React full case, with the same physical input and unchanged strict quality checks. Retain original Failed3 evidence, limits and incomplete cases throughout.
