# OV air selected frame — source and controlled test checkpoint

This package implements explicit complete-frame selection while preserving the existing request body {runId} as latest. It is a source/CPU checkpoint, not real SDK, GPU, converter, browser, mesh or solver acceptance. ROOT owns normal deployment and browser verification.

## Sources

source-final.json declares exactly 7 production files and 6 focused test files, with exact bytes and SHA256. full-source.diff is the full change against the preserved original producers, including the approved Kit extension and narrow handler scheduler closure. Each file also has a separate diff. Existing result discovery, result-layer publisher, protocol, project store, and Kit scene/grant/parser dependencies are bound separately. No protocol schema or grant authorization was expanded.

## Selected source and display

The backend accepts {runId} or {runId,time}. Explicit time must be a positive finite JSON number, with no Boolean, string, null, non-finite or huge-integer coercion. It uses the normal complete-root/common-contiguous-MPI discovery rule, preserves physical directory spelling, rejects ambiguous aliases and does not fall back to latest when an explicit frame is unavailable. Mirror conversion is injected in the tests. Case directory/version and selected mesh/fields/system/uniform-time signatures are checked before and after conversion. A failed or changing-source conversion is removed from its owned display mirror and cannot become a later ready cache hit.

Source signatures are stat/namespace display-cache signatures (including inode/device), not cryptographic content or engineering-quality certificates. Grant signing/TTL/roots and the separate quality/provenance authorization retain their existing contract. This slice does not broaden scientific acceptance.

The panel lists actual run times, keeps ordinary no-selection latest behavior, supports exact manual selection, and applies nearest/earlier-tie timeline selection. A plain per-project/run preference retains the exact frame and the snapped anchor across renderer remounts. A newer accepted Three selection is transferred without letting an older Three context overwrite an explicit OV choice. Fresh dataset ACKs must match the active run and granted frame; lifetime/generation checks suppress obsolete UI and preference writes. The single import queue replaces pending requests with the newest one. After a frame import, the actual saved volume, slice, stream and seed choices are reissued.

## Actual mutation ordering

Panel Promise tracking alone cannot establish completion of a legacy fire command: its promise resolves after transport send. The first Kit race packet proves dataset/scene interleaving only and is preserved unchanged.

The follow-up kit-display-order-v2 packet executes the actual router, handlers and scene loader AST against CPU fake Kit APIs. Corrected original-source tests demonstrate six old blocked writers overtaken by a new import and three queued fire commands touching a newer scene (9 FAIL). The implementation now executes the original coroutine under the same commit lock used for dataset/scene installation. Optional handler schedulers default to the original ensure_future; the bridge captures and awaits the one coroutine, and does not create a new fire ACK. Queued scene-generation mismatches are refused before parameter mutation. Volume/slice/readback ACK operations use the same barrier.

The no-yield receipt-order test confirms old fire finishes before the new import; a default-handler control confirms legacy scheduling and parameters remain unchanged. This prevents late stage writes in the tested normal display paths rather than merely hiding their ACK. Running old work is allowed to settle before the new frame/scene commits; this is not preemptive cancellation or a new latency bound. Unrelated legacy demo operations are outside this narrow guard.
