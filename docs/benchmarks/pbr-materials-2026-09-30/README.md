# 内置模型 PBR 材质与纹理回执(2026-09-30)——Three.js 与 OV 两端

用户要求:为软件内置模型在 Three.js 与 OV 两端添加更多材质和纹理,使其更真实。分支 `feat/pbr-materials`(7 个功能提交 + 合并 main `4e352128`)。

## 做了什么

- `tools/gen_pbr_textures.py`:确定性生成 7 套 512² 程序化 PBR 纹理(颜色/法线/粗糙度):拉丝不锈钢、铜、喷涂钢、管道保温层、镀锌钢、黄铜、橡胶;
  `--check` 验证逐字节可复现;清单 `src/frontend/shared/textures/generated_pbr_sets.json`,来源说明 `CREDITS.md`。
- `shared/js/pbr_materials.js`:两个编辑器共用的材质库;每个网格独占材质、纹理共享;按 (纹理, 平铺) 克隆,修掉"最后建的网格决定所有平铺"的旧缺陷。
- 液冷设备换装:管道=保温层(保留蓝/红供回水色)、机柜 manifold=按回路着色的不锈钢、设备支管=彩色橡胶软管、三通=不锈钢、
  闸阀=黄铜阀体+回路色法兰+不锈钢阀杆+橡胶手轮、CDU=粉末喷涂钢(保留青色)、冷板=铜;风管=镀锌钢。
- 房间反射光(RoomEnvironment,强度 0.5),只作用于新的 Standard 材质。
- OV 快照:纹理按图像内容去重;Phong 类导出预设粗糙度/金属度;机柜穿孔门导出为带 alpha 镂空的孔型纹理。
- 结果着色仍优先:有色部件的颜色贴图接近白色;Three.js 结果叠加克隆材质改色,Kit 液冷着色断开颜色贴图连接直接写结果色(`override_colours`),清除时精确还原。

## 如实登记

- **架空地板遮挡地板下管路(早于本分支)**:Shinaide 的主管、三通、阀门大多在 0.8 m 架空地板之下。地板在 main 与本分支都是 0.37 不透明度 + 纹理;
  Three.js 里呈现为可透视的暗色网格,RTX 里地板被照亮而板下处于阴影,管路只剩淡蓝色影子(`p-02`)。模型树隐藏地板后管路完整显示(`p-03`)。
  这也影响 Stage 4 的 OV 液冷着色可见性(管道/三通/阀门在板下)。候选:OV 结果着色时加适度自发光,或 OV 面板提供"隐藏架空地板"。本分支仅把地板导出的金属度 0→0.4、粗糙度 0.2→0.5。
- **同步耗时无实质回退(Kit 日志逐段计时)**:main 构建首次会话(2143 图元、3740 块):分块传输约 10 s、末段到开始编写 50.6 s、Kit 编写 63.5 s;
  PBR 构建(2231 图元含选中高亮、3409 块):约 10 s、46.0 s、68.6 s。早先整段计时 137/144 s 对 105/115 s 的差异是 40901 负载噪声(load ≈33)。
  真正值得优化的是每次同步都有的"末段 ~50 s + 编写 ~65 s"(与本分支无关),转 Stage 5 性能项。
- Three.js 结果着色保留近白颜色贴图的细微纹理,Kit 着色为纯色——两端都读作结果色,细节不同。
- 旧 HTML 页面(`--app html`)未做浏览器验收。
- 验收中另发现与本分支无关的 OV 缺陷:同一页面 OV→Three.js→OV 再进入时,WebRTC 插件报 `NVST_R_BUSY` 丢失场景 ack,页面降级为"未确认模式"
  (19:30 在 main 构建上也出现过同类 `NVST_R_BUSY` 突发,当时未落到最终 ack 上)。转 Stage 5:进度查询短超时重试 + Kit 场景状态查询确认最终载入。
