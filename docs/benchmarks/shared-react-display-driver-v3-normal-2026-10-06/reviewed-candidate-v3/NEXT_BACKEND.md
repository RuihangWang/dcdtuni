# Existing backend seams for shared OV conversion

This is the remaining implementation path, not an acceptance receipt. The current production route `/api/pp/render-source` is unconditionally 422 after its revision guard (server.py `handle_pp_render_source`). Kit `_trusted_result_context` begins None; render-result-layer begin/chunk/load remains rejected. The dataset display grant is intentionally not provenance: do not reinterpret it as a mesh/run/field certificate.

1. Extend the existing CachedPostProcessor native source snapshot, not a new numerical solver. `_state_lock`, `require_revision`, `_identity`, `_case_version`, `_source_info`, `run_dir`, the final boundary triangle cache, field cache, `get_slice`, streamline products and `get_volume` are the existing numerical/product sources. Server `_pp_revision_required` pins the snapshot while an endpoint reads it. Verify final native mesh/strict-quality receipt, source project/cfdrun hash, run receipt and field dimensions from authoritative runner/files before replacing 422. A stat meshSnapshotKey alone is insufficient; failed Shinaide stays diagnostic.
2. Reuse `ov_result_dataset.find_run` and exact numeric `_resolve_source` / `_resolved_signature` completeness and source-recheck semantics for frame binding. The pp runId is a path hash; the execution receipt uid may be different. Bind both rather than equating their spelling. Keep CASE_DIR_VERSION pre/post fences, complete common MPI time, no explicit-time fallback to latest, cache source revision, and existing owned output roots.
3. Publish a server-attested common numeric display product (surface patch array + every slice/streamline ID + the same volume grid). Retain request parameters, raw units, payload SHA and its accepted pp revision. Do not authorize a browser packet merely because it supplies matching expectedSource. The existing common CPU producer can assemble the display packet; the server must validate its numeric products against its own retained products/receipts, or issue/render the canonical server packet directly.
4. Add a separate exact grant kind alongside `display_grant.KINDS`, using the same managed HMAC key, TTL, nonce/root protections, to bind canonical payload SHA, accepted ResultSource, exact time, pp revision, project UID/content hash, scene revision and display generation. The existing dataset kind does not gain result authority. Kit verifies the grant and content hash, then sets the narrowly bound trusted context before its existing result_layers_usd path under the existing display commit lock. Extend `require_trusted_result_context` beyond source/time to the attested payload and current generation; verify at commit, not only on receive. Clear/expire context on new project/stage/run/frame and reject old same-client mutations.
5. Volume must consume the identical `CachedPostProcessor.get_volume(field, resolution)` regular grid (X-fastest layout, origin/spacing/dimensions/sentinel) that the public Panel already fetches. Retain/cache that grid under the pp revision and hash it. Lower that owned grid to a CAE dataset/IndeX input under the repository runtime/cache; do not silently voxelize the original unstructured dataset using a different resolution. The public VolumeIntent carries field/unit/range/palette/opacity/resolution. The existing scene `_apply_thermal_colormap` is fixed; replace its chosen RGB/alpha inputs with the same common 256-entry LUT and opacity realization, preserving missing-voxel masking and actual domain readback. Controlled LUT/alpha/grid tests precede real Kit/video validation.
6. Preview ring/seed conversion is display-only. Carry common display generation and concrete list/draft ID into Kit, then read back world-metre positions into `PostprocessDisplayDriver.interact`, which checks accepted generation/scope/set identity before updating the common forms. A drag moves a preview only; creating/re-cutting/re-tracing a set stays with the existing common Panel/backend products. Do not invoke the old Kit singleton slice/streamline numerical algorithm as a second owner. No guessed names or IDs.

The frozen dependency copies contain the actual source inspected for each seam. No backend changes, conversions, native runs, grants, Kit commands or API/browser operations were executed for this candidate.
