# Shinaide：地板开孔与设备脚印对齐，房间外壳闭合（2026-10-22）

**已修复。** 按 patch 列表逐例核对时，网格预览对 Shinaide 报“房间外壳缺失”（Wall_1–4、Floor_1、Top_1 没有 patch，网格出现 `domain_*` 六个面）。这不是误报：旧网格的流体域填满了带 0.25 m 余量的整个网格盒，房间墙、地板和天花板都不在边界上。

## 原因

`Floor_1` 带 20 个早期布尔减出的开孔（`geometry.cutouts`，`sourceName` 指向各机柜、ACU、CDU_Rack、UPS_Rack）。设备后来对齐过，开孔没有跟着改：每个开孔比设备当前脚印偏 1–10 mm。地板开孔与设备底面之间因此留下宽 2 mm 左右的缝，地板平面 y = 0 上的面片合计 71.0832 m²，房间是 9 × 7.9 = 71.1 m²，缺的 0.0168 m² 就是这些缝。气流经缝流到地板下、绕过墙体到达网格盒边界，墙面两侧都是流体，dcCart 便不给它们边界面。

`plane_cover.py <case> <y 平面> <x 平面> <z 平面>` 统计各 STL 在房间外壳平面上的面积，用它复查。

## 修法

把每个开孔改成其 `sourceName` 设备的当前脚印（取自同一次导出的 STL，地板局部坐标 u = x − x₀，v = z₀ + 7.9 − z），工程文件只改这 20 个多边形的坐标（400 行 diff），其余字节不变。之后经 React 编辑器重新导出、网格、求解。

| | 修复前（2026-10-21 网格） | 修复后（2026-10-22 网格） |
|---|---|---|
| 地板平面 y = 0 覆盖 | 71.0832 m² | 71.1 m² |
| 网格点范围 | x −0.2986…9.2014，y −0.2533…4.0533（整个网格盒） | x −0.0486…8.9514，y 0…3.8（房间内） |
| Wall_1–4 / Floor_1 / Top_1 | 无 patch | 2160 / 2160 / 1920 / 1920 / 13052 / 4608 个面 |
| `domain_*` | 6 个，带面 | 无 |
| 严格 checkMesh | accepted | accepted（`summary.json` 内的质量回执） |
| 收敛判定（回风 0.5 K 规则） | CONVERGED | CONVERGED，3000 步 |

四台 ACU 的回风温度在修复前后相差 0.1–0.5 K（`summary.json`，逐探针的末值与末窗峰峰值）。

## 下一步

设备移动后，布尔减出的开孔不会跟着移动，同类缝隙可能出现在其它工程里。下一步：导出时对房间外壳上带 `sourceName` 的开孔与源设备脚印做一致性检查并给出提示；网格侧已有的“房间外壳可能不封闭”日志警告同时显示到网格页状态栏。
