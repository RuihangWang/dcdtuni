# CDU canonical ports and authored routes: read-only audit

The actual saved main Shinaide scene contains two external U headers. Their intermediate points are authored routes. Both the existing display renderer and real v4 liquid input bind their connected endpoints to canonical CDU ports. Hiding or rerouting those external loops would change the visible meaning of the authored design.

The generic rear ports are 50 mm apart, but each pipe is 100 mm in diameter. Their terminal centreline segments approach the rear logical nodes from inside the cabinet. Endpoint identity alone does not establish a valid external rear-nozzle connection. The oblique finite TubeGeometry end rings extend about 45–46 mm beyond that rear plane. Authored external header extent, terminal surface excess and the physical port/route conflict are distinct findings.

The receipt binds the saved .cfdproj, real .liquidrun and primary shared source hashes and reconstructs the actual shared THREE renderer in memory. It records frames, original/bound waypoints and lengths, actual rendered bounds and position-buffer hashes. Centreline clearance is a segment-only calculation, not an exhaustive mesh intersection audit. No browser, model edit, server, CFD or GPU was used.

Liquid pipe buffers are display overlays outside the CFD/STL renderMeshes registry. OV serializes their actual buffers; a Three shader-only cut is not an equivalent OV change. The DAE graph independently consumes bound waypoints. Any later closed-cabinet display policy must preserve input bytes, routes/radii/topology, canonical ports and CFD/STL exports, retain the authored exterior headers and disclose the rear-nozzle/bottom-entry ambiguity. Editing spheres still use the saved raw waypoint coordinates.

No pipe source was edited. PDU identity remains unresolved; UPS_Rack was not relabelled.
