## Result and concrete issue

No P1 source-authority bypass was found in the frozen implementation. This is a source-only infrastructure review; B topology and C final native/product acceptance remain uncompleted. A remains conditional on the bounded API detail below and explicit mapping-only semantics. Source and existing fixture test records alone are not normal five-origin product validation.

**[P2] Reject excessive cell input before scanning it.** `dcCartCompleteCavityAuthority.H:97–103` checks authority/time/mesh dimensions, then loops over every caller-supplied `cells` entry at 100–101. The `maxCavityCells=128` rejection is only reached inside `Lineage::originsForCells` at `dcCartCompleteCavityOriginCore.H:203`. Thus an oversized list of valid/repeated live indices can be scanned arbitrarily long, without another remaining-clock check, before deterministic rejection. The list is already caller-owned, so this is an unbounded *work* path rather than a new large allocation in this function. Move empty/size >128 refusal before the loop. Preserve the existing duplicate rejection later. This affects the public future collection API; the current normal APP does not call this collection helper and no replacement is enabled. This is not evidence of a current production topology failure.

**Mapping contract clarification, not a discovered authority bypass.** `OriginCore.H:215–231` `compactKeys` verifies native-vector length, bounded compact count, nonnegative/in-range one-to-one bindings and full compact coverage; it intentionally copies unknown source key `-1` and still returns true. The minimal logical example is initialized active keys `[known,unknown]`, supplied native map `[0,1]`, count 2: mapping succeeds while an origin is unknown. This observation is direct source reasoning, not an executed probe. That behavior is suitable for a mapping-only helper which preserves unknown state. It must not be interpreted as origin permission. A future consumer must separately refuse unknown entries and call normal full-origin verification. The helper also has no remaining-clock callback and may traverse the full bounded dense directory: it must not be advertised as a checked complete-cavity authorization budget. Either document/rename the mapping-only result now or add a separate validated permission API later; do not silently drop unknown entries.

The frozen README paragraph 3/receipt lineage description overstates evidence by saying the real writer binding is exported: the helper has no production invocation in the frozen patch and the standard harness uses manually supplied `{1,-1,0}`. A future normal `writerBindings.cell` consumer is still required. This qualification resolves v1 A.6's source-authorization requirement without imposing it on a deliberately lossless mapping function.
