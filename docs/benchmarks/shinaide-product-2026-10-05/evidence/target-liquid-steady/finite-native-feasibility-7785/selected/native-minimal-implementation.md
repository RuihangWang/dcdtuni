# Finite native feasibility — implementation proposal, no C++ changes

The installed OpenFOAM core supplies LUscalarMatrix, simpleMatrix and QRMatrix linear systems. The scoped dcCart source inventory found no SQP, SLSQP or constrained quadratic-programming implementation. Dense linear algebra is sufficient infrastructure for four scalar parameters, but is not a tested constrained optimizer. This proposal therefore uses the direct finite algorithm that was independently exercised on actual 7785 R stencils. It needs scalar dot products and small arrays, not a new optimizer, Eigen package, SciPy binding or external native dependency. Inventory paths, primary header hashes and signatures are in primary-tool-inventory.json.

The C/H/app bytes remain ead4a057 / 4a5ef961 / babd07c8. These tests modify only new scratch point-file copies and mathematical documents. Actual job 7785 remains stock Failed3: D909/W100/R2. Its global N88.2022 degree ceiling is a warning constraint, not a replacement for a hard check. No native build, run, service, API, case-array, index or production-source change occurred.

## Minimal selection and proposal

1. Build cells() and pointFaces() once on the final installed polyMesh. Scan actual R failures first; use world-coordinate/topology keys for ordering, not source-parent/trace/case IDs. For an unprotected local internal triangular failing face, select a vertex whose complete incident star is interior, zone-free and triangular. This gives a three-coordinate pivot. If its other two vertices share a qualifying interior edge, test each coordinate axis for the exact geometric two-node mode described below and append one scalar. select_small_mode.py automatically derives both actual R choices from current topology.
2. The two nodes must have identical DP bits along the translation coordinate. Every incident non-triangular polygon must either have an exact constant coordinate in another axis (tangent motion), or lie on the translation-normal plane and contain both moved nodes at one exact secondary-coordinate level while all fixed nodes have one other level. The latter plane rotates; it is not fixed to the old internal support plane. A normal face containing only one moving node, a non-axis/warped unclassified face, an unknown zone identity, or any physical/coupled moving-node star refuses this narrow mode. Compute one shared translated coordinate and assign both nodes that same double. All seven actual rank1 polygons qualify without an epsilon classification or projection.
3. Normalize by the compact stencil span. Starting at zero displacement, take central finite differences with h=1e-5 of the target R objective and all proposal constraints. Choose one of four finite step radii (.004/.002/.001/.0005). Project the desired negative-gradient direction onto the fitted halfspaces and normalized trust bounds [-.08,.08]. The projection is direct bounded dual coordinate updates: lambda_i=max(0,lambda_i-slack_i) after row normalization; d += delta_lambda_i*a_i. At most 384 updates are allowed per attempt. Singular contradictory rows, nonfinite values or unmet residuals refuse the attempt. This is not claimed to solve every QP or to certify nonlinear feasibility.
4. Try the finite fractions 1,1/2,1/4,1/8,1/16,1/32. Accept a proposal iteration only after all fitted original-role constraints are reevaluated and the target improves. Stop at the target proposal reserve R>=.0105, a zero derivative, a rejected step, 32 iterations, 256 requests or 15 seconds. Every request checks the count and wall cap before evaluating. The reserve is an optimization stopping rule, not a change to the checkMesh .01 acceptance threshold. The current Python adapter computes fields twice per request; 168 requests therefore mean 336 vectorized field computations, plus setup and final audits. A native evaluator can reuse a single field result within a request, but that optimization has not been benchmarked.
5. Guard the final finite backtracks separately, including .95. Use true installed formula arithmetic, current accepted-neighbour geometry, complete moving-point star, all core faces, complete one-ring outside cells/faces and fixed second-halo values. Preserve original passing D/W/R/S roles, positive volumes, stock face-centre concavity and face-tet requirements, boundary/coupled/zone protection and cavity volume/first moment. Record N label exchange and enforce the measured global ceiling. Approximate proposal constraints and optimizer/projection success never authorize a point change. The long first run endpoint cleared R but added one D and was correctly rejected; its immutable negative result is retained.

## Eligibility and final installed gate

All stored coupled faces in the two finite stencils and previous fourteen-point stencil number zero. They do not demonstrate a moved-point or changed-owner cross-rank mode. A conservative first implementation can refuse a changed core with coupled faces and retain actual DP-identical unchanged outside owners. The earliest full installed writer certificate must still validate all coupled rings, point0/alias, CC/V/Sf/Cf and metadata after any batch update; remote qualities are not independently recomputed by these local proofs.

An interior-only implementation skips the earlier positive physical-flat node. Its complete physical star contains three triangles and one quad on a single exact written plane. An all-triangle-only physical predicate would also skip it. Supporting it later requires the independent fixed outer-ring, same patch/BC and zone, exact support-plane, positive pieces, area/first-moment footprint contract, rather than all physical-face coordinate bytes unchanged. The existing 1.6203125mm raw-STL normal deviation remains a recorded deviation and is not corrected or justified by this candidate.

Place the stage inside toPolyMesh after addZones and before the final earliest-baseline coupled certificate. Use owned local metric values; do not retain references through geometry-cache clearing. Commit accepted batches once through the official updateGeomPoints path with an unregistered NO_WRITE point field, explicitly clear/recompute tetrahedral base caches, force installed geometry, and rerun the combined hard-role/cavity and full coupled certificate. If anything fails, restore the complete original point batch and refresh, then refuse before writing. Bare plain-polyMesh movePoints can leave stale caches and is not an acceptable shortcut. Trial evaluations never construct a full mesh or write case files.
