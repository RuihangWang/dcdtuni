# Installed writer coupled certificate source proposal

This is an unbuilt, default-OFF AIR native proposal. The 38 Python tests check certificate semantics and frozen actual-fixture arithmetic; they do not run the new C++ or authorize a mesh. Existing APP533086/LIBc739b6 and all native cases remain unchanged.

The latest complete target remains rejected: ce81cb96 stock allTopology/allGeometry Failed3, D969/W100/R2/N763, S0. Its real CUA click-to-first-observed-terminal upper bound was 183.296 s and native generation 141.139 s. Neither value measures this new oracle.

## Why one complete installed oracle first

The four coupled owners from two real compact fixtures have identical before/after *writer-order* DP CC/V, but their source-CF result differs from writer order by 1–2 ULP. Their immutable independent proof is copied here as independent-writer-order-fixtures.json. Thus direct comparison to source-order ownCCVBytes would reject legitimate positives and would use the wrong baseline.

The source now invokes the SAME toPolyMesh once before any literal union, on a separate working deep copy of the immutable preoperator checkpoint. Its region has a distinct name, registerObject=false, NO_READ/NO_WRITE, and the explicit conforming-written TRACE block is disabled. Both point aliases and compact cell/face/point maps are returned through normal typed fields independent of TRACE.

All ranks execute the baseline call, even for zero certificates/empty local partitions. This preserves the existing writer patch-pruning collectives and constructor bounds synchronization. addPatches(false) is retained. No baseline mesh write, stock checker or remote geometry/quality query occurs.

The oracle forces the installed actual faceAreas/faceCentres/cellCentres/cellVolumes and stores owned values for every actual coupled patch, plus the existing conservative coupling-type protection list. PP role serialization is cached once per patch at max_digits10. Only startFace is omitted: native face -> actual compact face and patch-relative index independently bind the legitimate offset. nFaces, name/type, inGroups, processor ranks, neighbourPatch, referPatch, transform and every other emitted role field are preserved. Actual face-zone names/membership/flip are saved.

The immutable baseline keeps the *earliest raw cutMesh* checkpoint. The working copy, oracle polyMesh and temporary maps are destroyed before candidates. No candidate refreshes or overwrites the baseline. An outside coupled face missing from the real baseline is unsupported by candidate guards. Unknown coupled candidate types remain refused.

## Actual postwriter gate

After final addZones, normal maps bind the native face and owner, the compact face/owner, original native points, flattened alias representatives, compact point labels and the ordered world-coordinate ring. Compact numbers may differ between baseline and result; coupled alias membership, representatives, coordinate bytes, cardinality, orientation, canonical point0, patch-relative ordinal and roles may not.

The real final installed DP Sf/FC/CC/V is compared component-by-component using finite checks plus memcmp. Positive and negative zero differ; matching NaN/Inf is still refused. Only certificate-related original point aliases are compared, without imposing equality on unrelated interior compact labels.

One unconditional final reduction includes every local invariant and certificate IO failure; zero-certificate ranks participate. On failure, APP never reaches write(). Each rank preserves its raw PREOPERATOR arrays/metadata and baseline/final byte certificate for diagnostics; the altered candidate is not written as a mesh. On success, normal full checkMesh and all passing-role lineage remain necessary. A local JSON status is local-pass-awaiting-global; it is not global acceptance and does not claim remote quality recomputation.

Final certificate JSON contains actual final compact bindings and actual final installed bytes. It is not a copy of expected baseline data. The Python read-only tool compares emitted baseline/actual records, including full coupled census and empty-patch roles. Native global-zero evidence, reciprocal processor/cyclic written pairing and full stock checker evidence are separate requirements.

## Exact scope and default behavior

Only the existing default-OFF literal experiment constructs an oracle or holds checkpoints. Cavity/changed faces remain coupled/zone-protected. Local geometry, original facet role lineage, full affected five-metric gates and pair/round caps are unchanged. The normal writer returns typed maps only when requested or when a baseline exists; existing default mesh geometry/order is unchanged.

APP adds a stage budget check after the experimental final toPolyMesh returns. The actual full API watchdog and 300 s mesh deadline remain authoritative; a stage check cannot interrupt an overlong native call in the middle.

## Cost and memory accounting

For current frozen rank0, the written result had C=833839/F=2251326/P=591824. Four DP geometry caches alone need about 134.8 MB on that rank. The previously printed 1.81856 s includes other work and is NOT a pure writer benchmark.

Let S_cut be one cutMesh container-capacity payload estimate and S_poly be one polyMesh plus geometry/transient caches. Capture holds original m + raw checkpoint + working clone + S_poly. Its **incremental** peak is approximately 2*S_cut + S_poly + stored coupled certificates; allocator headers, point-canonicalization hash tables, temporary geometry reduction buffers and existing outer-scope cone arrays add overhead. The log reports S_cut for ONE payload and a geometry cache estimate, never RSS or total peak.

After capture, only one raw checkpoint and owned coupled certificates remain extra. The final phase briefly adds its actual coupled snapshot for proof output; it still constructs the normal required final mesh once. A conservative planning estimate is roughly 0.8–2 GB extra per rank / 6–16 GB across eight ranks; this is not measured RSS. Host available memory was about 227 GiB at read-only inspection.

Copy, actual installed construct/geometry, snapshot and final verification clocks are separate. PP serialization is cached by patch. This is one full oracle, not one full-mesh clone per candidate. Existing 1024-pair cap does not bound baseline or certificate wall time. Real whole API time including the new work must be <=300 s; no promise follows from current planning estimates.

A future sparse primitiveMesh oracle could avoid whole copies, but must prove the same aliasing, face-ring cleanup, orientation, internal sort ties, coupled order, cell owner/neighbour accumulation and final mapping. This first diagnostic deliberately uses the real writer instead of asserting those equivalences.
