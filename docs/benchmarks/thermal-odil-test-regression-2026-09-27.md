# Legacy thermal ODIL test investigation (2026-09-27)

Scope: `src/backend/tests/test_liquid/test_thermal.py::TestThermalLoop::test_converges` at `codex/liquid-control-platform@33c6c3ad`. This is the standalone Adam/ODIL test path, not the v3 Newton DAE experiment or the v1 production `hybrid_solve` entry point. CPU only; no Shinaide case or product code was changed.

The test uses the fixed `thermal_loop.liquidrun` fixture, manually seeds three edge flows at 6 kg/s and two junction pressures, then minimizes weighted squared residuals with Adam at learning rate 1.0 for at most 15,000 epochs. It asserts that the final logged total is below 1.0. Repeated runs with PyTorch 2.13.0 and `OMP_NUM_THREADS=MKL_NUM_THREADS=OPENBLAS_NUM_THREADS` set to 1, 2, and 4 all returned exactly `1.0551661036098123`; four other assertions in the same class passed on the one-thread run. The 2026-08-27 pre-MMS commit `620af9d8` also returned exactly the same value under the same local environment. This rules out the September DAE work and August MMS source hook as causes of this failure, and provides no evidence of thread nondeterminism.

The fixture's 15,000-step limit came from `83c9ea322` (2026-05-06), a test-runtime reduction from 30,000; the `<1.0` assertion had been set earlier in `db897620f` and was retained. Continuing the unchanged solver and inputs to 20,000 steps produced `0.9865894834920695`. At that point weighted mass residual `0.6727383478767289` and pipe initial-condition residual `0.31144199327740596` account for almost all of the remaining loss. At 15,000 steps they were approximately 0.673 and 0.379. Thus the failure is a deterministic legacy test-budget/threshold mismatch; passing at 20,000 is not proof of accurate mass conservation or a sufficiently small DAE residual.

The current v3 Newton path uses `DAEExperiment` and a common steady/Backward-Euler residual. Its targeted `test_dae_newton.py`, `test_dae_physical_mms.py`, `test_dae_experiment.py`, and `test_dae_runtime.py` tests passed, 20/20, in a two-thread CPU run. The v1 production `run_liquid_solve` dispatches to `hybrid_solve`, not this standalone Adam solve. The legacy ODIL module is still importable and could be used directly by research callers, so this result should remain visible in full-suite reports.

No threshold was relaxed and no solver change was made. If this legacy assertion must be green, increasing only its fixture budget to at least 20,000 epochs would reproduce a numerical pass here, but would add approximately five seconds and still check only an arbitrary weighted loss. A separate legacy-path test should quantify physical mass and initial-condition residuals before treating it as a correctness gate. This investigation does not validate the full backend suite, a live GPU run, or NV field data.
