# Pinned common toolbar contract

Only the three production targets in apply-map.json change. React remains the common Three/OV UI. The primary mode/renderer row and section tabs are siblings of the scrolling tools body; each active section uses the same full available width and existing grid gap. No modeling actions, time settings, scene data, rendering or liquid postprocess behavior changes. The rotation cube remains in the unchanged App center-view subtree and is independent of toolbar collapse.

PanelResizers measures unpinned header scrollHeight/rectangle, tools presence and existing timeline separately. Same-width header rewrap is observed through a real header ResizeObserver plus bounded text mutation observation; width/manual preference handling remains in the existing resizer. No active section means zero tools floor and no empty header-tools gap; mounted sections retain their state. Normal-sized layouts reserve the measured header, 32px active-tools floor, timeline and present gaps. At a smaller viewport hard cap, present regions and gaps receive bounded space at unchanged text size; header/tools are focusable scroll containers and existing timeline controls retain keyboard focus. This is graceful access under a physical height constraint, not a claim that all controls are simultaneously visible in a tiny viewport.

Header and tools observers are disconnected on unmount. The existing toolbar manual preference, panel width, auto/manual window caps and timeline state are unchanged. No stylesheet or component was edited in normal I/Main. No service, browser, API, Kit, GPU, Git or scientific worker was used.

Mounted tests use jsdom with explicitly controlled DOM dimensions. They exercise actual Toolbar and PanelResizers plus ResizeObserver/MutationObserver/keyboard events. They are not a browser layout engine and do not establish pixel beauty/alignment. A before-only synthetic header is inserted in the budget fixture to exercise the old resizer against the new public region layout; the independent structural test directly demonstrates the old primary/tabs belong to the tools scroll body. The before seven failures have overlapping causes and are not seven independent product bugs.

Browser acceptance remains with Root: expand each group, scroll tools to the bottom, confirm both header rows remain visible at ordinary heights, compare equal section width in compact/wide layouts, resize manually across header wrapping and timeline visibility, check extremely short height keyboard reachability and the independently mounted rotation cube. Shared engine switching, liquid floating result window, OV layout/source/pixel authority are outside this patch.
