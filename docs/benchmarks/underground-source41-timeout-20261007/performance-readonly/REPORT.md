# source41 carving: readonly performance audit

Bound to the actual owned build (41/41 source hashes held); four complete primary C/H files and original build binding are copied by value. No native/C/oracle was run. Runtime rank0's shell7 call took202s for44245 reached cells; shell8 began at203s. Root reports final nativeRC15 at299.764s. This fails the5min target; no checker acceptance is implied.

**Grouping and measured scope.** Surfaces.C1440-1524 creates shells by triangle vertex connectivity over each carving surface, independent of region labels. CutCells.C4728-4789 does reach/extract/carve once per connected shell, not once per six-faced region. Cells intersecting several shells are intentionally cut repeatedly. Region/source identity is retained by crossing regions and regionOfFace(C4357-4376,4423-4442). The202s timer surrounds carveShellPass(C4788-4797), excluding that shell's outer extract/writeBack; it still includes pre-split, classification and MPI waiting. No inner timing isolates the winding share, so the static hotspot below is not a measured202s attribution.

**Dominant complexity.** C3888 sets useWinding=closed. Every nearPoint not ON-by-distance calls solidShellWinding atC3955-3957. Surfaces.C1820-1836 scans ALL shellTris each call: three vector norms/square roots, cross/dot products and atan2 per triangle. Thus cost is near-points times entire-shell triangles, even for points far from most pipe facets. Shell7 has58850 local points; the near subset and per-shell facet count are not logged, so multiplying58850 by the total carrier248540 facets would overstate a measured count. In contrast shellDistance(C2616-2668) and box queries(C1681-1705/3029-3090) already traverse octrees; line hits(C1630-1677) query the surface tree and then filter shell IDs.

**Repeated work/allocation.** Outer parts copy all points/faces/cell metadata(C3230-3303), then write polygon vectors back(C3308-3330). Each pass rebuilds adjacency/eligible/point-anchor arrays(C3722-3800), and clipPass sizes per-face/chord vectors(C2073-2079). A long ring's bounding box includes its empty centre, increasing this local work. featurePreSplit(C2809-2815) materializes the whole shell triangle vector BEFORE returning for>500 facets. The server/frame recognition block(C3630-3698) likewise retrieves all triangles even for a surface whose name is not a server/frame. These are secondary unmeasured costs; the outer202s scope rules out blaming reach/extract alone.

**Narrow proposals preserving geometry, IDs and EPS (not implemented).**
1. First expose immutable shell triangle count/surface metadata from Surfaces.H. Apply the existing pre-split<2/>500 check before materializing tris; only build the server-box triangle vector for the same currently eligible named surface. Keep current thresholds and query order where triangles are used. Reuse scratch capacities, without moving merge/dedup or shell/pass order.
2. Eliminate duplicated closed-shell winding for halo copies with an exact fallback. Reuse the existing minRank owner rule(C3402-3422); owner computes the identical scalar sum. Nonowners may defer ONLY winding; retain their existing ON-distance/region data. Have the unchanged neighbour exchange mark actual received side values; any deferred point without an owner receipt computes the original local full sum after exchange. Never assume every foreign/standalone point is covered by the send band. This preserves the final side even when a halo receipt is absent and avoids inventing an MPI geometry rule.
3. Main asymptotic candidate: a per-shell triangle BVH with conservative solid-angle remainder intervals. Classify only when the interval, including floating error, excludes the ORIGINAL abs(sum)>2pi threshold; otherwise call the existing full scalar sum in original order. Triangle-area/distance-squared bounds provide a conservative geometric starting bound, but libm/accumulation error must also be certified. This changes no physical triangles and needs no approximate winding epsilon. Plain nearest-normal, unguarded sm.getVolumeType or unconditional parity is NOT an equivalent replacement: the current closed flag only checks edge incidence, not consistent orientation/self-intersections; solidShellInside(C1804-1816) queries the whole surface before nearest-shell filtering.

Future gates: exact old/new side+ON-region arrays on authored closed, open, nested, degenerate and MPI-owner/halo cases; identical source-region/cell provenance and strict checkMesh quality. Obtain per-shell inner timers/query counts before any speed claim. No source change or5min prediction follows from this read audit.
