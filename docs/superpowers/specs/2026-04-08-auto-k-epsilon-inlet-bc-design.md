# Auto-Compute k/epsilon Inlet Boundary Conditions

> **Goal:** Replace hardcoded k=0.001, ε=0.001 with physically derived values based on flow rate and patch area, preventing solver divergence from mismatched turbulence at inlets.

> **Architecture:** Compute patch areas from STL triangles in stlgen_runner, pass to FieldGenerator. For each flow-rate patch, calculate k and ε from standard engineering formulas (turbulence intensity + hydraulic diameter method).

---

## Problem Statement

All k and epsilon inlet values are hardcoded to 0.001 regardless of flow rate or patch size. For high-velocity inlets (e.g., ACU supply with Q=4 m³/s → U≈8 m/s), this creates a 100-240x mismatch between the imposed low-turbulence BC and the turbulence actually generated by the high-speed jet, causing k-epsilon to diverge within ~15 iterations.

## Formulas

Standard CFD engineering estimates (used by OpenFOAM, ANSYS Fluent, SimScale):

```
I = 0.05                              # turbulence intensity (5% for HVAC supply)
U = flow_rate / patch_area            # inlet velocity (m/s)
k = 1.5 × (I × U)²                   # turbulent kinetic energy (m²/s²)
D_h = 2 × sqrt(patch_area / π)       # hydraulic diameter approximation (m)
l = 0.07 × D_h                       # turbulence length scale (m)
C_μ = 0.09                           # k-epsilon model constant
ε = C_μ^0.75 × k^1.5 / l            # turbulent dissipation rate (m²/s³)
```

## Section 1: Compute Patch Areas from STL

**In `stlgen_runner.py`:**

New method `_compute_patch_areas()` that:
1. Iterates all STL files in `triSurface/`
2. For each solid, sums triangle areas using existing `_triangle_area_and_normal()`
3. Returns `Dict[str, float]` mapping sanitized solid name → area in m²

Called after `_load()` and before field generation. The result is passed to `FieldGenerator`.

## Section 2: Modify FieldGenerator to Accept Patch Areas

**In `fields.py`:**

`FieldGenerator.__init__` gets a new optional parameter `patch_areas: Dict[str, float] = None`.

The `_write_simple_scalar_field` method (which generates k, epsilon, nut, alphat, omega) is refactored:

- For **k field**: flow-rate patches get computed k values; walls keep `kqRWallFunction`
- For **epsilon field**: flow-rate patches get computed ε values; walls keep `epsilonWallFunction`
- For **nut, alphat, omega**: no change (keep current behavior)

## Section 3: Per-Patch k/ε Calculation

For each patch in the bridge_bc registry with `flow_rate > 0`:

```python
TURBULENCE_INTENSITY = 0.05  # 5% for HVAC
C_MU = 0.09

area = patch_areas.get(patch_name, None)
flow_rate = bc_info.flow_rate
if area and area > 0 and flow_rate and flow_rate > 0:
    U = flow_rate / area
    k = 1.5 * (TURBULENCE_INTENSITY * U) ** 2
    D_h = 2.0 * math.sqrt(area / math.pi)
    length_scale = 0.07 * D_h
    epsilon = C_MU**0.75 * k**1.5 / max(length_scale, 1e-6)
else:
    k = 0.001  # fallback
    epsilon = 0.001
```

Applies to bc_types: `acu_supply`, `acu_return`, `fan_inlet`, `fan_outlet`.

## Section 4: Internal Field Initial Values

Currently `internalField uniform 0.001` for both k and ε.

Change: compute the **average** k and ε across all flow-rate patches, use that as the internal field value. This gives a more reasonable starting condition.

Fallback: if no flow-rate patches exist, keep 0.001.

## Section 5: Backward Compatibility

- If `patch_areas` is not provided (old pipeline path), all values fall back to 0.001
- No changes to bridge_bc.py or cfd_export.json
- No changes to frontend
