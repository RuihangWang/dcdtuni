# GTC Dataset Regeneration — Design Spec

**Date:** 2026-06-29
**Author:** Tianyu (with Claude)
**Status:** Draft — awaiting user review
**Scope:** Generate a new 500-case GTC data-center CFD dataset by mirroring the `case/Slab_dataset/` pipeline, extended with **cabinet-count (geometry) variation**, and run it on NSCC ASPIRE2A.

---

## 1. Goal & Motivation

The existing GTC dataset is low-quality (insufficient design-variable diversity). Rebuild it as **500 stratified cases** spanning four load regimes (light / medium / heavy / super-heavy), varying:

- **Cabinet count** (true geometry change — racks present/absent among the 50 fixed slots)
- **Per-rack server fill** (which U-slots are populated), **per-server power & flow**
- **ACU supply temperature, supply flow, and on/off state**

Mesh-refinement and solver-convergence settings are **already authored** inside `GTC_2026.cfdproj` (`runDefaults`) and are **left untouched** (endTime = 1000 iterations, mesh base size 0.34 m, etc.).

This mirrors the proven `case/Slab_dataset/` generator, with the new geometry degree of freedom that Slab did not have.

## 2. Reference Scene (GTC_2026.cfdproj, schema v4 JSON)

| Element | Count | JSON location |
|---|---|---|
| Racks (cabinets) | 50 | `constructions.racks[m_1 … m_50]` |
| Servers (U-slot units) | 304 (~6/rack) | `constructions.racks[uid].constructions.servers[e_*]` |
| ACUs (CRAC units) | 6 | `constructions.acus[m_51 … m_56]` |
| Containment baffles | ~10 | `constructions.baffles[*]` |
| Room | 31 × 19.2 × 5 m | `geometry.{plane,height}` |

**Baseline values** (full config): server power 600–1988 W, server flow 0.042–0.264 m³/s; ACU supply 18.6–22.8 °C, ACU flow 5.1–6.5 m³/s; total room load ≈ 365 kW.

**Design-variable field paths:**

| Variable | Path |
|---|---|
| Server power (W) | `…servers[uid].cooling.power` |
| Server flow (m³/s) | `…servers[uid].cooling.volumeFlowRate` |
| Server U position / span | `…servers[uid].geometry.slotPosition` / `slotOccupation` |
| ACU supply temp (°C) | `acus[uid].geometry.faces[*].patches[*].physics.temperature` (where `role=="supply"`) |
| ACU supply flow (m³/s) | same patch `physics.volumeFlowRate` |
| ACU on/off | keep CRAC box geometry; strip supply/return patches → `acuSwitch=false` |
| Rack presence | delete `constructions.racks[uid]` object entirely |
| Containment baffle | `constructions.baffles[*]` — **regenerated by frontend on export, not hand-edited** |
| Case working path | `dctwinConfig.casePath` |
| Project name | `projectName` |
| Mesh/solver (untouched) | `runDefaults.meshConfig.*`, `runDefaults.simulationConfig.*` |

## 3. Design Variables & Load-Tier Table

Stratified Latin-Hypercube sampling (per Slab), four tiers. **These numbers are the proposed defaults — review and edit any cell.** ACU flow is micro-adjusted post-sample to keep the heat-balance ratio ∈ [0.3, 1.3] (Slab convention).

| Tier | Cases | Cabinets present (of 50) | Per-rack fill (U-load) | Per-server power | Per-server flow (m³/s) | ACUs on (of 6) | ACU supply T | ACU flow (m³/s) |
|---|---|---|---|---|---|---|---|---|
| Light | 100 | 12–22 | 0.05–0.20 | 0.4–0.9 kW | 0.03–0.08 | 2–3 | 20–24 °C | 3.0–4.5 |
| Medium | 150 | 22–35 | 0.20–0.40 | 0.8–1.4 kW | 0.06–0.13 | 3–4 | 18–22 °C | 4.0–5.5 |
| Heavy | 150 | 35–48 | 0.40–0.65 | 1.3–1.9 kW | 0.10–0.20 | 4–6 | 16–20 °C | 5.0–6.0 |
| Super-heavy | 100 | 45–50 | 0.60–0.85 | 1.7–2.2 kW | 0.15–0.27 | 6 | 15–18 °C | 6.0–6.8 |

Implied total room load spans ≈ 15 kW → ~650 kW. Per-tier sample counts sum to **500**.

**Key GTC-vs-Slab difference: minimum server U-span = 4U.** GTC server types/placement use only `slotOccupation ∈ {4, 6, 8}` U (Slab allowed 1U/2U). `fill_rack` never places a server smaller than 4U.

## 4. Sampling Methodology (`sampling_gtc.py` + `server_types_gtc.py`)

Mirrors `case/Slab_dataset/sampling.py` + `server_types.py`:

1. **Stratified LHS** (`scipy.stats.qmc.LatinHypercube`, seed=42) per tier. Dimensions: per-present-rack load levels + ACU supply temp + ACU flow.
2. **Cabinet count + subset:** sample `n_cabinets` from the tier range, then choose which of the 50 fixed rack slots are present.
   - **Default policy (review item):** *row-aware random subset* — fill rack rows with scattered gaps (a partially-deployed room), not a pure checkerboard and not strictly contiguous. Alternatives: pure random, or contiguous fill front-to-back.
3. **`fill_rack(load_level)`:** place servers into the 45 usable U-slots until the target fill fraction is reached, **minimum 4U per server**, sampling each server's power & flow within the tier range.
4. **ACU activation:** sample `n_active` of the 6 ACUs per tier; active ACUs get sampled supply temp/flow; inactive ACUs keep geometry but have supply/return patches stripped and `acuSwitch=false`.
5. **Heat-balance guard:** micro-adjust ACU flow so `Q_load / (Σ ṁ·cp·ΔT)` ∈ [0.3, 1.3].
6. **Labels:** every sampled value per case is recorded in `meta/sampling_plan.json` (the ML label file), plus `meta/server_types.json` and `meta/generation_log.json`.

---

## 5. cfdproj Mutation (`generate_cfdproj.py`)

For each case, deep-copy `template/GTC_template.cfdproj` (= `GTC_2026.cfdproj`) and:

1. **Delete absent racks:** remove `constructions.racks[uid]` (and their nested servers) for cabinets not present. *Do not hand-edit baffles* — the frontend's `full-pipeline` export regenerates the containment overlay + cutouts from the present racks.
2. **Populate present racks:** set each server's `cooling.power`, `cooling.volumeFlowRate`, `geometry.slotPosition`/`slotOccupation` (≥4U) per the plan; remove server objects for empty slots.
3. **ACU physics:** for active ACUs set supply-patch `temperature` + `volumeFlowRate`; for inactive ACUs **keep the CRAC box geometry**, strip supply/return patches, and set `acuSwitch=false` (verified Slab pattern — an idle CRAC is still physically present).
4. **Path rewrite (per new requirement):** set `dctwinConfig.casePath` to **the case's own folder** and `projectName = f"GTC_dataset_{idx}"`, so `Mesh/` and solve logs are written inside `case_XXXX/`.
5. **Leave `runDefaults` untouched.**
6. Write to `case_XXXX/GTC_dataset_XXXX.cfdproj`.

## 6. Repository Layout (mirror `case/Slab_dataset/`)

```
dcdtuni/case/GTC_dataset/
  GTC_2026.cfdproj                  # existing full-config base (kept)
  template/GTC_template.cfdproj     # copy of the base used by the generator
  server_types_gtc.py               # tiers + server (≥4U) power/flow model
  sampling_gtc.py                   # LHS + cabinet subset + fill_rack + heat balance
  generate_sampling_plan.py         # -> meta/sampling_plan.json (labels)
  generate_cfdproj.py               # plan -> case_XXXX/*.cfdproj (rack delete + path rewrite)
  meta/{sampling_plan.json, server_types.json, generation_log.json}
  case_0000/ … case_0499/           # one folder per case, cfdproj inside; Mesh/ + log/ land here
  run_nscc_pipeline.sh, *.pbs       # NSCC driver (Phase 2)
```

Case folders use Slab's `case_XXXX` (4-digit) convention for pipeline consistency. *(Review item: switch to `case_001` style if preferred.)*

## 7. Phase 1 — Local Generation (ends at HARD REVIEW GATE)

```bash
cd dcdtuni/case/GTC_dataset
python generate_sampling_plan.py --seed 42            # -> meta/sampling_plan.json
python generate_cfdproj.py --plan meta/sampling_plan.json \
       --template template/GTC_template.cfdproj         # -> case_XXXX/*.cfdproj
```

Produces all **500 `.cfdproj`** under `case_XXXX/`, plus the label files. **No NSCC, no solving yet.**

## 8. Phase 2 — NSCC Execution (only after approval)

Per the user's chosen path: upload the `.cfdproj` files and trigger the **complete pipeline by curling the dcdtuni frontend** on the cluster.

1. **Pull/refresh `dcdtuni` on NSCC**; build env (conda Python 3.10 + `module load openfoam`; install Playwright/Chromium for the headless export).
2. **Upload** the 500 `case_XXXX/*.cfdproj` to scratch (`/scratch/users/ntu/tianyu01/GTC_dataset/`). Rewrite `dctwinConfig.casePath` to the absolute NSCC case path (or pass `caseDir` via `set-case-dir`) so outputs land in each case folder.
3. **Per case:** start a dcdtuni server on the compute node and `curl POST /api/browser/full-pipeline {projPath}` → export (headless browser → STL + cfdrun, **regenerates baffles**) → blockMesh/snappyHexMesh → `buoyantBoussinesqSimpleFoam` solve. Poll job to completion; harvest the OpenFOAM result + the case's label row.

### NSCC facts (queue `q2`)
- Max **6 concurrent jobs/user**; ≤100 queued; array ≤1000; ≤24h walltime; 128-core nodes.
- Budget ≈ **100,000 SU** — tight; the pilot measures real per-case cost.

### PBS strategy (review item, decided at Phase-2 start)
- **Pack (recommended):** ~100 jobs, each one 128-core node running 5 cases × 24 cores; 6 concurrent → ~30 cases in flight. One dcdtuni server per node; exports serialized (fast), up to 5 solves concurrent.
- **Simple:** 500-wide array, 1 case × 24 cores; 6 concurrent → much slower.

## 9. Pilot (mandatory before full 500)

Run **5 cases** (one per tier + one heavily-reduced-cabinet case) on NSCC at 24 cores to:
1. Confirm the **headless browser runs on an NSCC compute node** (fallback: export locally, upload STL+cfdrun bundles, NSCC does mesh+solve only via `STLGenRunner`).
2. **Measure solve time → SU cost** → size walltime / cores / packing to fit budget with margin.
3. **Visually verify** the regenerated baffle on the reduced-cabinet case.

Then launch the full batch with a **staged ramp-up watch** (checks at ~1/3/5/15 min) and a **long-interval heartbeat** until completion (per CLAUDE.md long-job rule).

## 12. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Headless browser can't run on NSCC compute node | Pilot validates; fallback = local export + upload STL/cfdrun + NSCC mesh+solve only |
| Baffle regen wrong for reduced cabinets | Pilot visual check on a heavily-reduced case before full run |
| snappyHexMesh fails on some geometry subsets | `checkMesh` + per-case status in `generation_log.json`; regenerate failures with adjusted subset |
| SU budget exhaustion | Pilot-measured cost + pack strategy + conservative walltime |
| Disk-IO contention on NSCC scratch | Bounded concurrency (6 jobs); stagger I/O |
| Output not landing in case folder | `dctwinConfig.casePath` rewrite + `set-case-dir` verification in pilot |
