# SCANO 项目主页

论文式的中文项目展示页：讲清「一个 case、和 NVIDIA 生态什么关系、加速多少」，放论文配图与
Omniverse 渲染结果，并一键跳到实时演示。页面本身也是宣传视频的素材 —— 作者对它滚动录屏。

```bash
./serve.sh                 # 默认 :8090，DC_PAGE_PORT 可改
python3 verify_page.py     # 浏览器逐模块逐按钮验证（21 项）
```

```bash
python3 export_pdf.py      # 导出 PDF 到 export/（A4 分页版 + 连续单页版）
```

> **绝不要在本目录里直接跑 `python3 -m http.server`。** 那会把 `README.md`、`serve.sh`、
> `verify_page.py`（以及 `__pycache__/*.pyc`，里面内嵌同样的字符串）一并交出去。
> 只有 `public/` 是 web 根目录，`serve.sh` 已经把这条约束写死了。

## 为什么是独立静态页，而不是 Vite demo 里的一个标签页

审稿人点开论文链接时不该需要一块 GPU。这一页在 Omniverse 后端完全没启动时也应当可读，
所以它是纯静态的 HTML + 图片，**链接出去**而不是内嵌演示。

演示按钮的地址在页面加载时由 `location.hostname` 拼出，不写死。内网的笔记本打开
`http://<主机IP>:8090/` 时，按钮自动指向 `http://<同一主机>:8081/`——写死 `localhost`
会把每个人都送回他们自己的机器。

按钮指向的是 Omniverse 参考界面，端口固定为 8081。现在参考界面一律经仓库的启动器起，而启动器默认端口是
8000，所以演示前要显式写端口：`./src/start_server.sh --app omniverse --port 8081`（细节见
`cfd_demo/README.md`）。`verify_page.py` 的按钮 href 检查也按 8081 断言。

## 版式：明暗交替带

结构照 NVIDIA 自己的 AI-factory 页面来：深色带放 RTX 渲染与 CTA，**浅色带放白底论文图**。
这不只是节奏，也是把「白图贴黑底像没裁干净」这个问题从根上解决 —— 每种图都待在它该待的地方。
NVIDIA 绿 `#76B900` 只留给 NVIDIA 技术栈区块与演示 CTA，其余强调色仍是青蓝。

论文图另外走 `.paper`：白色衬底 + **只对衬底做羽化遮罩**。图片本体在 28px 白色留白之内，
被羽化掉的永远只是空白衬底，坐标轴与刻度一个像素都不会被吃掉。在浅色带上边界几乎消失，
在深色带上则是柔和渐变而非硬边框。

## 页面上的数字来自哪里

全部取自论文实测，不是示意值。改动前请回到原文核对。

| 页面上的值 | 出处 |
|---|---|
| ≈420×（392–447×） | 对 1000 步 8 核 CFD 求解，同机同并行现场计时 |
| 0.5–0.6 s | 热启动单 case 推理（特征已预计算） |
| 241 s（224–251） | CFD 求解器基线，4 个 case 均值 |
| 冷启动 9.4 / 7.2 / 7.3 / 2.1 / 1.9 s | 图 2 的分组柱值 |
| 2,152 GPU-hours | 10 个分支 × 2000 epoch 的训练开销 |

**演示的端到端耗时与论文的 0.5–0.6 s 不是一回事，页面里明写了。** 实测端到端 45–100 秒
（取决于是否要重跑 OpenFOAM 种子步），其中模型前向稳定在 14.4–14.7 秒，其余是未做优化的
工程开销：子进程启动、模型重载、重采样成 IndeX 能体素化的规则网格。别把这两个数字混用。

**加速比是下界。** 分母刻意取「停在完全收敛之前」的 1000 步求解，而不是生成标签用的完整
预算（百万单元热场 500 步 / 机房布局 5000 步）。页面正文写明了这一点，别在改写时丢掉。

条形图**不把 OpenFOAM 和代理模型画在同一标度上**。线性标度下 0.6 s 的条在 241 s 面前只有
两个像素宽，什么也读不出来；但只要按代理模型之间归一，最长的那根（0.81 s）就会和 241 s 那根
一样长，读者会以为两者相当。所以 OpenFOAM 那行画成**斜纹参考条**并标注「不按比例」，代理条
封顶 86%，永远短于它。改这段 JS 时务必保住这个区分。

## 多卡 TTA 那一节的数字

机制取自代码与论文双源核对：pivot 池用**与卡数无关的同一种子**打乱（`HomoGraph_dataset.py:516,524-527`）、
**连续等分**切给各 rank（`:529-539`，注释里写明是从交错改过来的）、各 rank 持整图尺寸缓冲、
`all_reduce(SUM)` 后除以逐节点计数（`runner.py:1599-1620,1533`）、后端 NCCL（`inference.py:56`）。

**别把「多卡 = 提速」写成普遍结论。** 决定精度的是**累积重叠趟数**，不是卡数：
论文用 1 卡×20 趟（0.6018）对 6 卡×4 趟（0.5986）验证过。本演示 ρ 钉在 0.02，
总趟数恒为 50，所以卡数只影响墙钟；论文用 ρ=1.0，每卡一趟用完自己那份，
R 卡就是 R 趟累积，精度随之变（layout 单流 0.3488@R=1 → 0.1948@R=6，`appendix.tex:609`）。

本机实测（case0，各 3 次）：1 卡前向 14.29 s / nRMSE 0.192502；2 卡 8.45 s / 0.192518 —— 1.69× 且精度不变。
**3 卡及以上在本机稳定失败**（rank 0 报 `CUDA-capable device(s) is/are busy or unavailable`，空闲卡上可复现，未定位）。

## 「OpenFOAM」→「CFD」的口径统一

网页、PPT、PDF 的正文与演讲者备注里不再出现 OpenFOAM，统一说 CFD 求解器。**替换不是全局 sed**：
「用 OpenFOAM 跑 1000 步」这类作主语的地方补成「CFD 求解器」才读得通，作定语的地方才用「CFD」。

三张论文配图里的字是烤进像素的，处理方式不同：

| 图 | 做法 |
|---|---|
| `hero_speedup.png` | **从源头重生成**。`Gen-FVGN` 的 `cases/Figure/make_hero_figure.py` 已加 `FIG_SOLVER_LABEL` / `FIG_OUT_DIR` 两个环境变量：`FIG_SOLVER_LABEL=CFD FIG_OUT_DIR=<目录> python3 make_hero_figure.py` |
| `cost_cold_warm.png` | **改图例文字**。其输入 `cases/GTC/{A1..C2}/.../sweep_table.csv` 五个全部不存在（`cases/GTC` 整棵树已删，只剩 `cases/GTC_new`），无法重生成 |
| `fields_3d.png` | **改列标题**。脚本 1419 行且要从 17 GB vtu 做三维渲染，代价远大于改一行标题 |

后两张的改法：先量出原文字的**墨迹包围盒**，用 matplotlib（与原图同一渲染器、同一 dpi）反解字号
重绘同款文字再贴回。反解得到 6.7pt / 16.6pt，墨迹宽度与实测分别差 0 和 1 像素，所以字重字号与
相邻标签完全一致。**数据像素一个没动，只改了标签。**

**论文原图保持 OpenFOAM 不变**，这是刻意的：论文正文通篇用 OpenFOAM，配图若改成 CFD 就会与自己的
caption 打架，何况正在盲审。两个脚本的默认行为未变，只有传了环境变量才产出 CFD 版本。

## 导出 PDF

`export_pdf.py` 不是简单调一次 `page.pdf()`——直接导会**静默丢信息**，因为两个交互图表
（冷/热成本、1/2/6 卡切分）在 PDF 里点不动，只会印出当前那一个状态。脚本因此把每个图表的
**全部状态都渲进去**：成本图左右并排，多卡图三态纵向排开。另外展开 `<details>`、去掉吸附导航
与浮动按钮、给图加 `break-inside: avoid`。

导出时有个坑：成本图必须**先切状态、等 1.1s 过渡走完、再取 outerHTML**。
`renderBars` 在脚本初始化时就把 `#bars` 捕成了闭包变量，不按 id 重新查询，
所以「先克隆再让克隆体重绘」是无效的——两栏会印出同一组数字，而且不报任何错。

演示地址在页面上由 `location.hostname` 运行时拼出，导出会把它固化成导出机的地址。
脚本把它换成 `http://<演示主机>:8081/`：印 localhost 对读者无用，印内网 IP 则是在一份
会外传的文档里写进机构网段。两个产物的文本层都实测过，敏感串命中为 0。

两个产物用途不同：`SCANO_项目主页.pdf` 是 A4 横向分页（26 页，用来发送/打印）；
`SCANO_项目主页_单页.pdf` 是一整张连续长页（约 15100px 高，屏幕阅读时与浏览器里完全一致）。

## verify_page.py 覆盖什么

每一项都在交互**之后**回读 DOM 取值，不从源码推断「handler 接上了」：七个导航锚点的定位与
高亮、冷/热切换是否真的换了数字、A/B 手柄拖动后遮罩宽度、A/B 两帧是否同尺寸铺满容器、
六张 OV 渲染是否真的解码成功、折叠的审稿向图能否展开、灯箱开关、BibTeX 复制反馈、
三个演示按钮的实际 href、回顶按钮，外加破图与 JS 运行时错误检查。

两个曾经真实发生、并被这套检查抓到的坑：

* **A/B 底图 `height:auto` 不能省。** `<img>` 带了 `width`/`height` 属性（用来在解码前预留
  盒子，避免滚动录屏时版面跳动），这两个属性是 presentational hint：`width:100%` 盖掉了宽度
  那个，但没有 height 规则时 `height="588"` 仍然生效，底图被渲染成 1190×588 塞进 851px 高的
  容器里，横向拉伸且下方露黑。`p7b` 就是盯这个的。
* **拖动必须能取消入场自动扫。** A/B 进入视口时会自动扫一遍（0.94 K 的差别太细，静止不动
  看起来像坏了）。若用户在这 2.6 秒里抓住手柄，动画会逐帧覆盖他的拖动、结束时再归位 50%。
  `sweepLive` 标志让任何触摸立即取消动画。
